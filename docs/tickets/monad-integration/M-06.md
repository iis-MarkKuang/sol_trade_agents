# M-06: Arb strategy generalization (N-chain pairwise)

Status: done
Delegation: high
Depends on: M-02
Blocks: M-08

## Goal

Generalize `backend/src/strategy/strategies/cross-chain-arb.strategy.ts` from a
hardcoded `['solana', 'injective']` two-chain comparison to an N-chain pairwise
scan driven by a `chains: ChainId[]` option + per-pair `bridgeCostBps` map, so
adding Monad produces Solana↔Monad and Injective↔Monad signals automatically.
Backward-compatible: the 2-chain case is a 2-element list.

## Non-goals

- Do not wire real bridge execution (signals stay research-only).
- Do not modify the frontend arb panel (M-07).
- Do not change the `CrossChainArbSignal` field names beyond widening the
  `buyChain`/`sellChain` union.
- Do not add new REST endpoints; the existing `/realtime/cross-chain/arb`
  call site passes the new options.

## Constraints (red lines)

- `CrossChainArbSignal.buyChain`/`sellChain` widen from `'solana' | 'injective'`
  to `ChainId` (includes `'monad'`). Existing consumers (frontend, NL agent)
  must still compile — they treat these as strings.
- `detectArb` options gain `chains?: ChainId[]` (default
  `['solana', 'injective']` to preserve current behavior) and
  `bridgeCostBps?: Record<string, number>` (keyed by `"solana|injective"`-style
  pair ids; default keeps the existing flat 25 bps for solana↔injective).
- For each shared asset, compute the mid on every chain in `chains`, then emit
  one signal per unordered chain pair whose `netEdgeBps >= minNetEdgeBps`.
- `bridgePath` string generalized: `"deBridge: <buyChain> -> <sellChain>"`.
- No float for bps/edge — integer bps throughout (already the case).
- No real RPC; the strategy consumes `NbboSnapshot` objects already in memory.
- When `chains` has < 2 entries, return `[]` (nothing to compare).
- Existing solana↔injective signal output must be byte-identical when
  `chains` is unset (default) — regression guard.
