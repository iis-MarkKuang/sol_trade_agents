# M-07: Frontend (Monad pairs in dropdown + chain badge)

Status: not-started
Delegation: medium
Depends on: M-05
Blocks: M-08

## Goal

Add the Monad pairs (`MON/USDC`, `WBTC/USDC`, `WETH/USDC`) to the Live Trading
page pair dropdown with a `Monad` chain badge, and ensure the Prepare Trade flow,
lifecycle buttons, Trade Event Feed, and Recent Trades render Monad routes
correctly (the `DexQuote.chain` field already drives rendering; this is mostly
the dropdown + badge).

## Non-goals

- Do not add a new page; extend `LiveTradingPage.tsx` only.
- Do not implement Monad-specific UI components beyond the chain badge.
- Do not wire real signing in the browser; lifecycle buttons stay mock-execute.
- Do not change the Insights page.

## Constraints (red lines)

- The pair list must come from the backend's supported pairs (or a shared
  constant); do not hardcode Monad addresses in the frontend.
- Chain badge: `Solana` (existing), `Injective` (existing), `Monad` (new) —
  consistent styling.
- When the backend has `ENABLE_MONAD=false`, Monad pairs should not appear
  (either filtered by a `/realtime/supported-pairs` endpoint or omitted from a
  shared list). Prefer not showing pairs the backend can't quote.
- No secrets in the frontend bundle.
- No real wallet connection; the wallet field stays demo-only.
- TypeScript build (`tsc -b && vite build`) must pass.

## Context

- `frontend/src/pages/LiveTradingPage.tsx` — pair dropdown, Prepare Trade form,
  lifecycle buttons, nBBO snapshot, arb scanner, event feed, recent trades.
- `frontend/src/lib/api.ts` — API client; pair list + chain badge source.
- `backend/src/config/tokens.ts` — `ALL_PAIRS` (M-02 adds Monad pairs).
- Design: `docs/monad-integration-research.md` §4.8.
