# M-02: Token registry (MONAD_TOKENS, MONAD_PAIRS)

Status: not-started
Delegation: low
Depends on: M-01
Blocks: M-03, M-06

## Goal

Add `MONAD_TOKENS` (ERC-20 addresses + Pyth feed ids) and `MONAD_PAIRS` to
`backend/src/config/tokens.ts`, merge them into `ALL_PAIRS`, and update
`chainOfPair` so Monad pairs are correctly recognized. Use placeholder ERC-20
addresses marked `TODO: verify against Monad ecosystem contracts` where the
canonical address is not yet confirmed.

## Non-goals

- Do not create the DEX adapter (M-03) or executor (M-04).
- Do not wire into realtime (M-05).
- Do not modify the frontend pair list (M-07).
- Do not fetch live token metadata from Monad RPC.

## Constraints (red lines)

- `MONAD_TOKENS` uses the `TokenInfo` shape; Monad tokens carry an `address`
  field (ERC-20) rather than `mint` (Solana) or `denom` (Injective). Add an
  optional `address?: string` to `TokenInfo` in `types.ts` if not present.
- `MONAD` native token: decimals 18, no `address` (native gas token); wMON has
  the wMON ERC-20 address (TODO placeholder).
- `USDC`/`USDT`/`WBTC`/`WETH` reuse the existing Pyth feed ids from
  `SOLANA_TOKENS`/`INJECTIVE_TOKENS` (same assets, same oracle).
- `MONAD_PAIRS` sets `chain: "monad"` explicitly on every pair.
- `chainOfPair` must return `"monad"` for pairs with `chain === "monad"` or
  with a base carrying `address` and no `mint`/`denom`. Order of checks:
  explicit `pair.chain` → `denom` (injective) → `address` (monad) → `mint` (solana).
- `ALL_PAIRS` merge must not shadow existing Solana/Injective pair symbols.
  Monad pairs use distinct symbols (`MON/USDC`, `WBTC/USDC`, `WETH/USDC`).
- `pairSymbolForChain` must return Monad pair symbols for BTC/ETH/MON.
- No real RPC calls.
