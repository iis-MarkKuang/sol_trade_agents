# M-01: Chain abstraction + config

Status: not-started
Delegation: low
Depends on: (none)
Blocks: M-02, M-03, M-04, M-05

## Goal

Extend `backend/src/types.ts` with the `"monad"` chain id, a `monad_dex` dex source,
and a `MonadExecutionPlan` interface, and add a `monad` config block to
`backend/src/config/config.service.ts` plus matching `backend/.env.example` entries.
No runtime behavior changes yet — everything is additive and gated behind
`ENABLE_MONAD=false`.

## Non-goals

- Do not create the DEX adapter or executor (M-03, M-04).
- Do not add Monad tokens/pairs to the registry (M-02).
- Do not wire anything into `realtime.service.ts` (M-05).
- Do not modify the frontend.
- Do not run a live Monad RPC call.

## Constraints (red lines)

- `ENABLE_MONAD` defaults to `false`; when false, `ConfigService.monad.enabled`
  returns `false` and no Monad code path activates.
- `ChainId` gains `"monad"` as a third member; existing `"solana" | "injective"`
  consumers must still type-check (no narrowing breakage).
- `DexSource` gains `"monad_dex"`; existing `RiskPolicy.allowedDexes` typing
  still compiles.
- `MonadExecutionPlan` mirrors `InjectiveExecutionPlan` shape (side, amount,
  price, notionalUsd, reason) plus EVM-specific fields (chainId, dex, tokenIn,
  tokenOut, minAmountOut, to, deadline).
- `TradeExecutionPlan` gains an optional `monadExecutionPlan?` field — additive only.
- No secrets in source. `MONAD_PRIVATE_KEY` stays in `.env.example` as empty string.
- No float for amounts; `amountIn`/`minAmountOut` are strings (human-readable).

## Context

- `backend/src/types.ts` — current `ChainId`, `DexSource`, `InjectiveExecutionPlan`,
  `TradeExecutionPlan`.
- `backend/src/config/config.service.ts` — existing `injective` config block as the
  shape template (enabled flag, network, api urls, mnemonic, markets override).
- `backend/.env.example` — existing `Injective integration` section as the comment
  style template.
- Design: `docs/monad-integration-research.md` §4.1 and §4.7.
