# T-02: Redis client module (shared ioredis instance)

Status: done
Delegation: low
Depends on: (none)
Blocks: T-04

## Goal

Add a small NestJS module that exposes a single shared `ioredis` client
constructed from `REDIS_URL`, with a health check and graceful shutdown. No
business logic; just the wiring so later tickets can inject a Redis client.

## Non-goals

- Do not implement any budget counting, reservation, or ledger logic.
- Do not replace BullMQ's internal Redis usage.
- Do not add a new Redis dependency; `ioredis` is already in `package.json`.
- Do not hardcode any proxy or host; use `REDIS_URL` only.

## Constraints (red lines)

- The client must read `REDIS_URL` from `ConfigService.redisUrl` only; no
  hardcoded `redis://localhost:6379` in source.
- Must implement `onModuleDestroy` to call `client.quit()`.
- Connection failure must not crash app startup silently; log a clear error
  and let Nest fail or degrade explicitly (do not swallow and continue as if
  healthy).
- No real Redis connection in tests; mock the client.

## Context

- `ioredis` ^5.3.0 is already a dependency.
- `ConfigService.redisUrl` already returns `this.config.REDIS_URL`.
- `bullmq` already uses Redis but owns its own connection; this module is for
  the UsageLedger hot path only.
- Follow the existing module pattern in `backend/src/` (e.g. how
  `PrismaModule` exposes a shared client).

## Verification

- `npm run build` passes.
- `npm test` (existing 13 suites / 41 tests) still passes.
- `git diff --check` clean.
- New module is registered in `AppModule` only if it does not break existing
  tests; if registration requires a live Redis, gate it so tests still pass
  without Redis (see Tests).

  - `onModuleDestroy` calls `quit()` on the client.
- Add `backend/src/redis/redis.service.spec.ts`:

- All tests mock `ioredis`; none connects to a real Redis.
