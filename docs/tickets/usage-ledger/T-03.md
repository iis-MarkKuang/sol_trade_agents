# T-03: ConfigService usageLedger config block + tests

Status: done
Delegation: low
Depends on: (none)
Blocks: T-04

## Goal

Extend `ConfigService` with a `usageLedger` getter that parses a feature flag
and per-provider hard-limit / warning-percent config from env, following the
existing `numberFromString` / `booleanFromString` pattern. No runtime consumer
yet.

## Non-goals

- Do not add the Redis client or the ledger service.
- Do not modify existing config getters (`coinmarketcap`, `dune`, `llm`,
  `decision`, etc.).
- Do not change `.env` (only `.env.example`).
- Do not pick final limit values; use clearly-marked placeholder defaults and
  document them as pending OP-14.

## Constraints (red lines)

- All numeric values must be bounded with `Math.max` / `Math.min` like the
  existing getters (no unbounded env input).
- `warningPct` must be clamped to `[0, 100]`.
- `hardLimitPerDay` must be `>= 1` for each provider.
- The feature flag must default to `false` (off).
- Do not print or log any key.

## Context

- `backend/src/config/config.service.ts` has the `ConfigSchema` (zod) and the
  getter pattern. Add new fields to the schema and a new getter.
- `backend/src/config/config.service.spec.ts` already tests bounded provider
  usage controls; extend it.
- `backend/.env.example` documents every env var; add the new ones with
  comments noting OP-14 pending.
- Design sketch: `docs/usage-ledger-design.md` "Budget config sketch" has the
  shape.

## Verification

- `npm run build` passes.
- `npm test` passes (including the extended config spec).
- `git diff --check` clean.
- With no new env vars set, `config.usageLedger.enabled` is `false` and all
  limits equal the placeholder defaults.

## Tests

Extend `backend/src/config/config.service.spec.ts`:

- `usageLedger.enabled` defaults to `false`.
- Setting `USAGE_LEDGER_ENABLED=true` flips it.
- Each provider's `hardLimitPerDay` and `warningPct` parse from env and are
  bounded (e.g. `warningPct=150` clamps to `100`, `hardLimitPerDay=0` clamps to
  `1`).
- Existing tests remain green (no regressions to other getters).
