# T-04: UsageLedgerService core (reserve / record / rebuild / budget check)

Status: done
Delegation: high
Depends on: T-01, T-02, T-03
Blocks: T-05, T-06, T-07, T-08, T-09

## Goal

Add a `UsageLedgerService` that provides the provider-neutral primitives every
integration ticket will call: `reserve(provider, date, estUnits)`,
`recordActual(reservationId, units)`, `recordFailed(reservationId)`,
`recordCacheHit(provider, date, queryKey)`, `checkBudget(provider, date)`,
and `rebuildCounters(date)` for cold start. PG is the source of truth; Redis
holds atomic daily counters that are rebuilt from PG on cold start.

## Non-goals

- Do not integrate any provider (Dune/CMC/LLM/JEV) in this ticket.
- Do not add an HTTP API (that is T-09).
- Do not implement the orphan-reservation reconciliation job; note it as a
  future task only.
- Do not call any real Redis or Postgres in tests.

## Constraints (red lines)

- PG is the only durable record. Redis is a cache of aggregates, never the
  source of truth.
- `rebuildCounters` must sum `usage_event` for the given UTC date and set
  Redis counters to match; it must not blindly INCR.
- Budget check (`checkBudget`) must use Redis INCR atomically; the PG
  `reserved` write and the Redis INCR are not atomic together — this is
  accepted, but the hard limit is enforced by Redis, and PG is the audit
  record.
- When `usageLedger.enabled` is `false`, every method must no-op or return a
  permissive result so current behavior is unchanged. This is the safety gate.
- When Redis is unavailable, behavior is governed by OP-12 (not yet decided);
  until OP-12 is resolved, fail closed (throw) and log, do not silently fall
  back. Document this clearly in code comments.
- No float for counts.

## Tests

Add `backend/src/usage-ledger/usage-ledger.service.spec.ts`:

- `enabled=false`: `reserve` / `recordActual` / `checkBudget` no-op and return
  permissive values; Redis and Prisma mocks are never called.
- `enabled=true`:
  - `reserve` INCRs Redis for `(provider, date)`, writes a `reserved` PG row,
    returns a reservationId.
  - `checkBudget` returns `allowed=false` when count exceeds hard limit; returns
    `warning=true` when count >= hard * warningPct/100.
  - `recordActual` writes an `actual` PG row linked by reservationId.
  - `recordFailed` writes a `failed` PG row.
  - `recordCacheHit` writes a `cache_hit` row with `units=0` and does not INCR.
  - `rebuildCounters` sums PG for the date and SETs Redis (not INCR).
- All Redis and Prisma interactions are mocked; no live connections.
