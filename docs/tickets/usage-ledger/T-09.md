# T-09: Usage summary read API endpoint

Status: done
Delegation: medium
Depends on: T-04 (and at least one of T-05..T-08 for meaningful data)
Blocks: (none)

## Goal

Add a read-only HTTP endpoint that returns current usage per provider for a
given date (default today UTC): reserved, actual, failed, and cache-hit
counts, plus the hard limit and warning threshold from config. This is the
observability surface for the ledger; it lets the operator see budgets
without querying the DB directly.

## Non-goals

- Do not add write endpoints; the ledger is written only by services.
- Do not add authentication in this ticket (OP-10 covers API auth; flag it).
- Do not build a frontend dashboard; return JSON only. Frontend wiring is a
  separate, later ticket.
- Do not aggregate over arbitrary date ranges in this ticket; support a
  single date (today by default, optional `?date=YYYY-MM-DD`).

## Constraints (red lines)

- Read-only: no mutations. The endpoint must only `SELECT` from `usage_event`
  and read config.
- When `usageLedger.enabled=false`, return an empty/`disabled` payload with a
  clear flag, not an error.
- No secrets in the response (no API keys, no query SQL bodies unless
  scrubbed; `queryKey` is a hash/label, which is fine).
- Numeric counts are integers.
- Must not require a live Redis; it can read from PG directly for the
  summary (Redis is only for the hot-path atomic check).

## Context

- T-01 provides the `UsageEvent` model to query.
- T-03 provides the hard limits / warning thresholds to surface.
- Follow the existing controller pattern (e.g. `OfflineAgentController` under
  `/agent`). Suggest route `GET /agent/usage?date=...` or a new
  `UsageController`; pick whichever matches existing conventions.
- OP-10 (API auth) is unresolved; add a code comment that this endpoint is
  unauthenticated and must be gated before public exposure.
