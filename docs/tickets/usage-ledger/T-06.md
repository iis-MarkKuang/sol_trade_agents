# T-06: CMC — add daily credit budget via UsageLedger

Status: done
Delegation: medium
Depends on: T-04
Blocks: T-09 (partially)

## Goal

Give `CoinMarketCapCrawlerService` a persistent daily budget via
`UsageLedgerService`, so CMC credit consumption is bounded across restarts and
instances. Today CMC has only a TTL cache and no daily cap.

## Non-goals

- Do not change the CMC API call, response parsing, or CoinGecko fallback
  logic.
- Do not decide the metering unit; OP-13 (credits vs requests) is unresolved.
  Implement against a configurable `unitKind` and default to `requests` until
  OP-13 lands, with a code comment flagging the decision.
- Do not remove the CoinGecko fallback; it stays as the degradation path when
  CMC fails (separate from budget exhaustion).

## Constraints (red lines)

- When `usageLedger.enabled=false`, no ledger calls; CMC behaves exactly as
  today (TTL cache, no daily cap).
- When `enabled=true` and the daily budget is exhausted, behavior follows
  OP-11 (unresolved). Until then, fail closed: skip the CMC call and proceed
  to the existing CoinGecko fallback (do not crash the whole pipeline). This
  is a budget gate, not a hard pipeline failure.
- Cache hits must call `recordCacheHit`, not consume budget.
- No real CMC calls in tests.

## Context

- `backend/src/crawlers/coinmarketcap-crawler.service.ts`:
  - `cacheTtlMs` from `configService.coinmarketcap.cacheTtlMs`.
  - The cached-listings path (line ~86) is the cache-hit branch.
- T-04 provides the ledger primitives.
- `coinmarketcap-crawler.service.spec.ts` already tests cache reuse without
  consuming a credit; extend it.

## Verification

- `npm test` passes.
- `git diff --check` clean.
- `enabled=false`: identical to today.
- `enabled=true`: cache hit records a cache_hit; fresh CMC call reserves then
