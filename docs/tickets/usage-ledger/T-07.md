# T-07: LLM — persist usage_metadata via UsageLedger

Status: done
Delegation: medium
Depends on: T-04
Blocks: T-09 (partially)

## Goal

Replace the log-only LLM token usage in `LlmAgentService` with a persisted
`actual` UsageLedger event, so token consumption is durable and counts toward
the LLM daily budget. Keep the existing log line for operator visibility.

## Non-goals

- Do not change the LLM prompt, sampling, or adapter selection.
- Do not add a pre-call reservation for LLM in this ticket (LLM cost is small
  and per-request; reservation is optional and deferred). Only record `actual`
  after the call. Note this as a deliberate simplification.
- Do not integrate JEV (T-08).

## Constraints (red lines)

- When `usageLedger.enabled=false`, behavior is exactly today: log the
  `usage_metadata` and do not call the ledger.
- When `enabled=true`, write an `actual` event with `provider="llm"`,
  `model=<resolved model>`, `unitKind="tokens"`, `units=total_tokens` (or
  `input+output` if total is missing). Never write `NaN` / `undefined`; fall
  back to `0` and log a warning if usage is missing.
- No real LLM calls in tests; mock the adapter as today.
- No float for token counts.

## Context

- `backend/src/agents/llm-agent.service.ts` line ~65: reads
  `response.usage_metadata` and logs it.
- `ConfigService.llm` provides the resolved `provider` and `model`.
- T-04 provides `recordActual`.
- `llm-factory.spec.ts` and any existing LLM tests must stay green.

## Verification

- `npm run build` passes.
- `npm test` passes.
- `git diff --check` clean.
- `enabled=false`: no ledger call, log line still appears.
- `enabled=true`: after a (mocked) LLM call, `recordActual` is called with the
  token counts; the log line still appears.

## Tests

Add or extend a spec for `LlmAgentService` (likely a new
`llm-agent.service.spec.ts` if none exists, following the factory spec style):

- `enabled=false`: ledger mock not called; `invoke` mock returns content; log
  captured.
- `enabled=true` with `usage_metadata` present: `recordActual` called with
  `provider="llm"`, correct model, `units=total_tokens`.
- `enabled=true` with `usage_metadata` missing: `recordActual` called with
  `units=0` and a warning logged; no throw.
- LLM adapter is mocked in all cases.
