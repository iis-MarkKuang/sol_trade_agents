# T-05: Dune — migrate in-process budget to UsageLedger

Status: done
Delegation: high
Depends on: T-04
Blocks: T-09 (partially)

## Goal

Replace `DuneCrawlerService`'s in-memory `executionsToday` / `assertExecutionBudget`
with `UsageLedgerService` so the Dune daily execution budget survives restarts
and is shared across instances. When the ledger flag is off, current behavior
is preserved exactly.

## Non-goals

- Do not change the Dune SQL, result mapping, or caching logic.
- Do not add CMC / LLM / JEV integration (separate tickets).
- Do not change the Dune API call itself; only the budget gate and the
  usage-recording around it.
- Do not implement the reconciliation job for orphan reservations.

## Constraints (red lines)

- When `usageLedger.enabled=false`, `assertExecutionBudget` must behave
  exactly as today (in-process counter, reset at UTC midnight). This is the
  fallback safety path.
- When `enabled=true`, the hard limit comes from
  `config.usageLedger.dune.hardLimitPerDay`, not the old
  `DUNE_MAX_EXECUTIONS_PER_DAY`. Keep the old env var as the fallback when the
  ledger is off.
- Over-limit behavior follows OP-11 (not yet decided). Until OP-11 is
  resolved, fail closed (throw the existing-style error). Do not silently
  continue.
- No real Dune calls in tests; the Dune HTTP layer stays mocked as today.
- Cache hits must call `recordCacheHit` (units=0), not consume budget.

## Context

- `backend/src/crawlers/dune-crawler.service.ts`:
  - `assertExecutionBudget` (line ~279) and `executionsToday` / `executionDay`
    fields.
  - `executeSql` (line ~222) calls `assertExecutionBudget` before the HTTP
    call and increments `executionsToday` after.
  - `fetchOnChainData` (line ~145) checks `cachedRows` before calling
    `fetchFreshOnChainData` — this is the cache-hit path.
- T-04 provides `UsageLedgerService.reserve / recordActual / recordFailed /
  recordCacheHit / checkBudget`.
- The existing `dune-crawler.service.spec.ts` must stay green; extend it.

## Verification

- `npm run build` passes.
- `npm test` passes (existing Dune spec + new cases).
- `git diff --check` clean.
- With `usageLedger.enabled=false`, the Dune spec behaves identically to today
  (no ledger calls, in-process budget still enforced).
- With `enabled=true` (mocked ledger): a cache hit calls `recordCacheHit` and
  does not call `reserve`; a fresh fetch calls `reserve` then `recordActual`
  on success or `recordFailed` on error.

## Tests

Extend `backend/src/crawlers/dune-crawler.service.spec.ts`:

- `enabled=false`: existing behavior unchanged; `UsageLedgerService` mock is
  never called.
- `enabled=true`, cache hit: `recordCacheHit` called once, `reserve` not
  called, no HTTP call.
- `enabled=true`, fresh fetch success: `reserve` called, HTTP mocked, then
  `recordActual` called with the execution count.
- `enabled=true`, fresh fetch failure: `reserve` called, HTTP throws, then
  `recordFailed` called.
- `enabled=true`, budget exhausted: `checkBudget` returns `allowed=false`,
  `executeSql` throws the budget-exhausted error without calling HTTP.
