# T-08: JEV — persist usage via UsageLedger (optional)

Status: done
Delegation: medium
Depends on: T-04
Blocks: T-09 (partially)

## Goal

Persist JEV decision-provider token usage via `UsageLedgerService` so the
quality-gate calls count toward a daily budget, mirroring T-07 for LLM.

## Non-goals

- Do not change the JEV quality-gate mode logic (`disabled` / `shadow` /
  `enforce`).
- Do not change the JEV API call, response parsing, or confidence handling.
- Lowest priority of the integration tickets; can be deferred until after
  T-05..T-07 and T-09 land.

## Constraints (red lines)

- When `usageLedger.enabled=false`, no ledger calls; JEV behaves exactly as
  today.
- When the quality gate mode is `disabled`, do not record usage (no call is
  made).
- When `enabled=true` and mode is `shadow` or `enforce`, write an `actual`
  event with `provider="jev"`, `model=jevModel`, `unitKind="tokens"`.
- JEV currently returns HTTP 451 in some regions; tests must not make real
  calls. Use the existing contract/mock pattern.
- No float for token counts.

## Context

- `backend/src/decision/adapters/jev-decision.adapter.ts` and
  `jev-decision.adapter.spec.ts`.
- `backend/src/decision/research-quality-gate.service.ts` invokes the adapter.
- `ConfigService.decision` provides `jevModel` and `qualityGateMode`.
- T-04 provides `recordActual`.

## Verification

- `npm run build` passes.
- `npm test` passes.
- `git diff --check` clean.
- `enabled=false` or mode `disabled`: no ledger call.
- `enabled=true` and mode `shadow`/`enforce`: `recordActual` called after a
  (mocked) JEV response.

## Tests

Extend `backend/src/decision/adapters/jev-decision.adapter.spec.ts` (or the
quality-gate spec, wherever the JEV call is mocked):

- `enabled=false`: ledger mock not called.
- mode `disabled`: ledger mock not called.
- `enabled=true`, mode `shadow`, JEV mocked success: `recordActual` called
  with `provider="jev"` and token counts.
- `enabled=true`, mode `shadow`, JEV mocked failure: `recordFailed` called.
- No real JEV HTTP calls.
